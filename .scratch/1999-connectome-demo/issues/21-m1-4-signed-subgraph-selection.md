# 21: M1.4 增強 300 點＋抑制 200 點的子圖選取與可達性

**Blocked by:** None（工作票 18 已完成；本機已重建 M1.1 資料）

**Status:** completed (2026-11-13)

## 背景

使用者要求子圖仍為 500 點，其中 300 個增強點、200 個抑制點。目前的 500 點是從 seed `274013289` 以 hash-priority BFS 擴展兩層得到的，2,216 條邊，沒有符號資訊（工作票 04、05）。

## 已決定

- **D1 不使用排名。** 使用者放棄「前 N 大」排名，因為從全腦排名會讓點非常分散、邊很少。改用下面的「名額限制 BFS」。
- **D3 範圍：從單一起始點做名額限制擴展。** 使用 M1.2 的 BFS 和 hash-priority 規則（BLAKE2b-128，salt `FlyCallM12-v1`）。
- **D3b 起始點（2026-11-13 決定）：** 原 seed `274013289` 不在神經傳導物質表內，改用同一個 hash-priority 規則，但候選只限有符號的神經元（163,856 個，兩種麩胺酸版本的候選集合相同），取優先值最小者：
  - **新 seed `810979`**（優先值 `0000050e8f76202aa7b64373197210ca`）
  - `consensus_nt` = acetylcholine（+1），cell type `IN07B098`
  - 用同一函式 `streaming_bfs._hash_priority` 重算舊 seed，得到與工作票 04 記錄相同的優先值 `000000101b2e…`，確認規則一致。
  - cell type 前綴 `IN` 看起來是腹神經索（VNC）的中間神經元命名，代表子圖可能位在 VNC 而不是腦部。這屬於工程取樣，不是生物學選擇；建圖後要用腦區或 cell type 摘要確認並寫進報告。
  - **原 D3 的「與 G0 同一起點」不再成立。** 工作票 22 比較 G0 與 G1／G2 時，要說明點集合、起點與組成都不同，G1 − G0 不能解讀成單純「換點」的效果。
- 腦區限定（規格書待老師討論第 2 題）留作之後的實驗，不在本工作票範圍。
- **D5 I/O 選取規則（2026-11-13 決定）：**
  - 輸入點：照 M1.3 規則（keyed hash-priority，salt `FlyCallM13-IO-v1`）選 32 個。
  - 輸出點：只從「非輸入、且在 T=2 內可由任一輸入沿有向邊到達」的點中，用同一 salt 的 `output` 優先值取前 32 個。
  - 可達性由構造保證；這是固定規則，不是搜尋 salt。原 M1.3 規則選出的輸出點仍記在 manifest 的 `m1_3_rule_output_node_ids`。

## 選點規則：名額限制 BFS

1. 從 seed `810979`（D3b）開始，用和 M1.2 相同的無向 BFS 往外擴展；同一層內依 hash-priority 排序，保證可重現。
2. 依序檢查每個候選點，符號由工作票 18 的主要規則 `sign_glu_inhibitory` 決定：
   - +1 且增強名額還沒滿 300 → 收入
   - −1 且抑制名額還沒滿 200 → 收入
   - 該符號名額已滿 → 跳過（不收入、也不從它往外擴展）
   - 調節型、缺值、信心不足（工作票 18 排除的點）→ 跳過
3. **只從已收入的點往外擴展。** 因此選出的點在無向圖上一定連通。
4. 兩個名額都滿（共 500 點）就停止。
5. **停止條件（執行前寫定）：** 最大 BFS 深度與最大掃描次數要在執行前寫進 manifest。超過上限仍湊不滿就停下來回報各符號已收的數量，不可自行放寬名額或改變規則。
6. seed 本身如果被排除或名額不符，就停止並回報，不自行換 seed。

## 要做的事

- 實作名額限制 BFS（擴充 `streaming_bfs.py` 或新模組），先用 fixture 測試，再對官方資料執行。fixture 要涵蓋：
  - 名額
  - 跳過規則
  - 只從已收入點擴展
  - 列順序不影響結果
  - 停止條件
- 取這 500 點之間所有原始有向邊（induced subgraph），不新增、不刪除邊。
- 重做 M1.3：選 32 個輸入點、32 個輸出點，確認每個輸出點在 T=2（模型主設定）內，可由至少一個輸入點到達。輸入／輸出點的符號組成要寫進 manifest。
- 同一組 500 點要輸出三份符號設定，供工作票 22 使用：
  - G1：全部 +1
  - G2：主要規則（Glu = −1）
  - G2-glu+：敏感度版本（Glu = +1）。點集合不變，只改麩胺酸點的符號。

## 驗收條件

- manifest 記錄：
  - seed、BFS 規則、名額、跳過規則、停止條件、實際走到的深度
  - 點數與邊數、+1／−1 點數、各符號的出邊數
  - 連通性摘要、I/O 可達性
  - 所有 checksum
- 相同設定重跑要得到相同 checksum。
- 邊數由資料決定，不要求等於 2,216。
- 可達性不通過時，依事先寫定的規則重選 I/O，或明確停止。
- 不得用人工生成的圖代替真實 connectome。
